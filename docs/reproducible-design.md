# Luorong Notes 可复现设计规范

本文档描述当前 Astro 版本的视觉、交互与扩展边界。目标不是复刻某个现成桌面，而是将 Niri 的纵向工作区、DMS/Quickshell 的稳定系统壳、macOS 的小组件桌面和 Android 的移动分页组合成一套一致的博客界面。

## 1. 产品定位

博客首先是可阅读、可归档的静态站点，其次才是一套桌面隐喻。

- 壁纸提供个人桌面环境感。
- 应用栏负责稳定导航，不承担长篇信息展示。
- 主页是小组件和未来小应用组成的桌面。
- 归档、分类和文章是统一窗口框架中的应用。
- 动画是可关闭的增强，不能影响普通链接、静态构建和内容可访问性。

## 2. 系统层级

所有页面共享三层空间关系：

1. 壁纸层：铺满视口，不随路由切换。
2. 系统壳：应用栏、主舞台底板和反向圆角，不随路由切换移动。
3. 应用层：主页桌面或应用窗口，是唯一参与页面转场的区域。

桌面端示意：

```text
┌───────┬──────────────────────────────────────────────┐
│       │ 桌面主页，或带标题栏的应用窗口               │
│ 应用栏│                                              │
│       │                                              │
└───────┴──────────────────────────────────────────────┘
```

主页主舞台上、下、右侧贴合视口，只露出左侧两个圆角。归档、分类和文章页面在主舞台内部使用四周留有间隙的大型应用窗口。手机端取消窗口外间隙和外轮廓圆角，优先保证连续阅读。

## 3. 应用模型

### 3.1 固定应用

应用栏永久保留三个入口，顺序不得因路由或动态内容改变：

1. 主页；
2. 归档；
3. 分类。

应用配置集中在 `src/config/apps.ts`。图标、标签、路由和顺序以该注册表为准，不应在各页面重复维护。

### 3.2 动态阅读器

打开文章后，固定应用下方出现一个阅读器图标：

- 阅读器只有一个动态槽位；
- 打开另一篇文章时更新该槽位，不增加第二个图标；
- 离开文章页面后图标继续存在，可重新打开最近阅读的文章；
- 阅读器标题栏提供关闭按钮，关闭后清空动态槽位和阅读位置；
- 关闭导航使用历史替换，刷新或后退不得让刚关闭的阅读器复活；
- 当前阅读位置保存在当前浏览器标签页的 `sessionStorage` 中；
- 刷新或路由转场时不得先消失再出现。

### 3.3 应用栏形态

桌面端应用栏固定在左侧，不展开、不推动主舞台，也不显示常驻文字。图标名称通过 tooltip 和可访问名称提供；活动应用使用稳定的底板或状态点，不改变图标坐标。

手机端应用栏移到底部，采用四个固定槽位。前三个槽位始终对应主页、归档、分类，第四个槽位只显示动态阅读器。阅读器出现时，前三个图标不能发生水平跳动。

## 4. 主页桌面

### 4.1 网格注册表

主页采用 `n × m` 网格。每个小组件在 `src/config/widgets.ts` 中声明：

- 唯一 `id`；
- 桌面位置和跨度；
- 平板位置和跨度；
- 手机位置和跨度；
- 手机所在页码。

新增小组件或未来小应用时，先扩展注册表，再添加内容组件和必要样式。不得重新把整个主页写成一组不可拆分的页面级定位规则。

宽屏桌面使用 `8 × 3` 网格，单元格最大为 `174px`，整个网格在可用桌面区域居中。平板和手机使用 `4 × 5` 网格；手机通过页码将对象分布到两页。注册表允许保留未占用单元格，留白属于桌面构图的一部分，不需要用无意义内容补满。

### 4.2 首版桌面对象

信息小组件包含：

- 时间；
- 用户信息；
- 最近文章；
- GitHub 活动；
- 博客统计。

独立应用图标包含：

- 用户头像；
- 明暗主题切换；
- 主题库入口；
- GitHub；
- 邮件。

博客统计使用构建阶段可确定的数据，例如文章篇数、总字数、分类数和最近更新日期。没有可靠数据源时不得伪造访问量。

### 4.3 视觉层级

桌面对象不是传统仪表盘卡片墙：

- 只有需要扫读动态信息的对象使用小组件外框；
- 命令、外链和个人入口使用固定尺寸的应用图标与图标标签；
- 每个小组件只表达一个主要任务；
- 最近文章最多显示四条紧凑记录；
- 不在卡片内部继续嵌套卡片；
- 通过壁纸间隙、尺寸差异和内容密度建立主次，壁纸应始终可见；
- 桌面宽屏保留明确的空网格，为壁纸和未来小应用留出空间；
- 4K 屏幕只增加桌面留白，不扩大网格单元和应用图标。

### 4.4 手机分页

手机主页参考 Android 桌面，使用横向分页和滚动吸附：

- 当前版本为两页；
- 页面下方显示可点击的分页点；
- 每页使用四列网格；
- 只有主页允许横向翻页；
- 归档、分类和文章页面只做纵向滚动；
- 小组件内部不得再形成独立的长滚动区。

## 5. 应用窗口

归档、分类和文章共享同一窗口框架：

- 统一标题栏；
- 统一背景、边框和外轮廓圆角；
- 统一内容滚动容器；
- 标题栏展示关闭按钮、应用图标、应用名、简要状态和时间；
- 页面内容只负责自身业务，不重复创建另一层外框。

归档保持时间线式高密度列表；分类以主题和文章数量为主要扫描线索；文章正文控制可读行宽，代码块和表格可以在自身容器中横向滚动。

桌面宽屏文章显示右侧大纲。平板和手机均使用正文上方默认折叠的大纲按钮，避免透明文字压在壁纸上，也避免大纲持续挤压正文。

## 6. 纵向工作区转场

桌面端参考 Niri 的上下工作区关系。应用顺序由 `src/config/apps.ts` 决定：

- 打开应用栏中更靠下的应用时，旧应用向上退出，新应用从下方进入；
- 返回更靠上的应用时，旧应用向下退出，新应用从上方进入；
- 同一阅读器内切换文章时只做短距离淡入替换；
- 壁纸、应用栏和系统壳保持静止；
- 不使用旋转、大比例缩放、模糊或三维翻页。

动画总开关位于 `src/config/site.ts`：

```ts
pageTransition: {
  enabled: true,
  durationMs: 320
}
```

将 `enabled` 改为 `false` 后，站点不加载 `ClientRouter`，所有链接回到浏览器原生导航。关闭动画不需要修改任何页面组件。

手机端、`prefers-reduced-motion` 和浏览器不支持 View Transition 时不播放应用转场。快速连续导航后，最终 URL、活动图标和内容必须属于最后一次导航。

## 7. 响应式规则

### 7.1 宽屏桌面

- 左侧固定应用栏；
- 主页采用八列、三行网格，单元格最大 `174px`；
- 网格在可用桌面内水平和垂直居中，4K 下不拉伸组件；
- 小组件在一屏内完成主要展示；
- 应用窗口与视口之间保留一致间隙；
- 文章正文与右侧大纲并排。

### 7.2 平板与窄桌面

- 继续保留左侧应用栏和桌面系统壳；
- 主页改为四列、五行网格；
- 应用窗口半径略小，但仍与系统壳共享同一变量；
- 文章大纲切换为折叠按钮；
- 所有关键控件应适合鼠标和触摸混合使用。

### 7.3 手机

- 不显示桌面左栏和旧式顶栏菜单；
- 应用栏固定在底部并计入 `safe-area-inset-bottom`；
- 主页使用横向分页；
- 应用页面不播放路由转场；
- 应用窗口贴合屏幕，不保留桌面外间隙；
- 页面底部内容不得被底栏遮挡；
- 页面本身不得出现非预期横向滚动。

当前样式以 `1279px` 区分宽屏和平板，以 `820px` 进入手机布局。断点用于表达布局能力，不应被业务代码用来判断内容语义。

## 8. 圆角与主题

系统外轮廓使用 `--system-radius`：

- 宽屏桌面为 `24px`；
- 平板为 `20px`；
- 手机应用窗口为 `0`；
- 主舞台左侧圆角、反向圆角和应用窗口必须引用同一变量；
- 内部组件可以使用较小的派生半径。

主题数据位于 `themes/*.json` 和 `themes/index.json`。亮色与暗色主题分别保留用户最后一次选择，主页快捷按钮只切换明暗模式，主题面板用于更换两种模式对应的具体主题。

所有主题必须保证正文、弱化文字、链接、活动图标和代码块背景具有可辨认的对比度。装饰色不得直接成为整页文字颜色。主题切换只能由明确的按钮触发，点击导航、文章或空白区域不得改变主题。

## 9. 静态内容与数据

- 文章来自 `content/articles/*.md` 和 Markdown frontmatter；
- 站点与用户信息来自 `content/site.json`；
- 主题来自 `themes/`；
- GitHub 热力图由构建脚本写入 `src/data/contributions.json`；
- 构建失败时优先使用仓库中的现有热力图快照；
- 外部数据失败不得阻断文章阅读和站点导航；
- 令牌只在构建环境使用，不进入浏览器产物。

最终产物仍是 `dist/` 中可部署到 GitHub Pages 的静态文件。桌面交互不要求运行时服务器或数据库。

## 10. 可访问性与状态

必须保证：

- 图标按钮具有可访问名称；
- 关键触控区域至少接近 `44 × 44px`，底栏应用达到 `48 × 48px`；
- 键盘焦点清晰，不被装饰层遮挡；
- 当前应用、当前主题和当前手机页可以被识别；
- 动态阅读器隐藏时不进入键盘顺序；
- 主题面板使用原生对话框语义，并可关闭；
- 动画遵循减少动态效果偏好；
- 头像、壁纸、主题或活动数据失败时，局部降级而不是破坏整个页面。

## 11. 扩展入口

新增固定应用：

1. 在 `src/config/apps.ts` 注册顺序、图标和路由；
2. 新增 Astro 页面；
3. 通过 `BaseLayout` 选择对应应用窗口信息；
4. 保持手机底栏槽位策略稳定，必要时再设计分页或应用抽屉。

新增主页小应用或小组件：

1. 在 `src/config/widgets.ts` 增加类型和三档布局；
2. 在主页渲染对应组件；
3. 控制单一职责和固定尺寸；
4. 在 3840、1440、1280、900、390、320 六档验证溢出、触控和信息密度。

## 12. 验收清单

### 系统壳

- [ ] 壁纸和应用栏在路由切换中保持静止；
- [ ] 固定应用顺序始终为主页、归档、分类；
- [ ] 动态阅读器最多一个，离开文章后仍可重开；
- [ ] 阅读器可从标题栏关闭，刷新和后退不会立即恢复已关闭的文章；
- [ ] 主舞台、反向圆角和应用窗口使用同一半径来源；
- [ ] 主题面板或应用栏不会推动主内容布局。

### 桌面与平板

- [ ] 3840 宽屏主页网格保持尺寸上限，壁纸在网格四周可见；
- [ ] 1440 宽屏主页主要内容在一屏内，仍保留壁纸空间；
- [ ] GitHub、邮件、主题与外观入口使用独立应用图标，不合并成链接面板；
- [ ] 刻意留空的网格位置不会被组件自动拉伸填满；
- [ ] 1280 窄桌面主页无横向或纵向溢出；
- [ ] 900 平板网格无重叠，文字不溢出；
- [ ] 归档、分类和文章共用一致的大型应用窗口；
- [ ] 宽屏文章显示侧边大纲，平板显示折叠大纲；
- [ ] 上下转场方向与应用栏相对顺序一致；
- [ ] 转场期间无白闪、底色跳变和错误活动状态。

### 手机

- [ ] 320 宽度应用图标、分页和最近文章不横向溢出；
- [ ] 390 宽度不出现旧式顶栏和展开菜单；
- [ ] 底栏前三个固定图标不会因阅读器出现而移动；
- [ ] 主页分页点与当前横向页面一致；
- [ ] 横向手势只作用于主页桌面；
- [ ] 文章大纲默认折叠；
- [ ] 页面结尾不被底栏遮挡；
- [ ] 路由切换不播放桌面应用动画。

### 功能与主题

- [ ] 动画总开关关闭后所有导航仍然可用；
- [ ] 同一地址重复点击不会造成收缩、展开或重载闪烁；
- [ ] 主题只由主题控件切换；
- [ ] 所有内置主题下文字和背景可清楚区分；
- [ ] `npm run check` 与静态构建通过；
- [ ] 无 GitHub 令牌时仍可使用已有数据完成构建。
